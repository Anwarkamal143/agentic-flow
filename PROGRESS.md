## Known limitations

- Onboarding wizard (#114, ADR-0074): the basics, harnesses and GitHub steps write no configuration (the workspace root, Harness and Token Reference live in bootstrap `config.json`, written only by `factory init`); the Project step registers by local path only and sets no setup command or required checks (`repo profile set` does). The wizard is offered, never forced.
- Config import (#113, ADR-0073): an import never deletes a Project or Repository the file leaves out, and never registers a Repository or sets its GitHub Coordinates, source or detection-only profile fields (detection status, CI files). The Token Reference (`config.json`) is neither exported nor imported.
- Phase D (decided, Q34): Projects can't be deleted or renamed, and a Repository can't move to another Project. Events and audit refer to them; no exit test needs it.

49. **D2's ready-wait is measured in milliseconds, which flakes under load (2026-11-28, flaky-test fix).** ADR-0058 defines a claim's ready-wait as `task.claimed − task.ready|created` (or `stage_run.running − stage_run.queued`) in time, and its own Consequences note that a Project's wait on its own limit can dominate.
