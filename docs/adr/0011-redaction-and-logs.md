# Redaction and factory logs (Phase A, issue #11)

Choices made so that secret values never reach history, and so that `factory logs` can show a Job's Harness and verification output. All are routine and reversible.

- **What counts as a secret.** ARCHITECTURE §17: "known secret patterns plus the values of any environment variable marked secret". There is no configuration for marking a variable yet, so a variable of the runtime's environment is marked secret by its name: it ends in `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `API_KEY`, `ACCESS_KEY`, `PRIVATE_KEY` or `CREDENTIAL(S)` (`GH_TOKEN`, `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `DB_PASSWORD`, …). The factory's own API token is always a secret (`FACTORY_TOKEN`). Values shorter than 8 characters are not redacted, since replacing them would mangle ordinary text. The known patterns are a small Phase A set: AWS access key ids, GitHub tokens (`gh[pousr]_…`, `github_pat_…`), Anthropic keys (`sk-ant-…`) and private key blocks, including a block cut off by output truncation. The full corpus is Phase E (E3). The rule is the pure `secretsFromEnv` / `createRedactor` in `@factory/domain`.
- **The replacement names the secret, never its value**: `[REDACTED:GH_TOKEN]`, `[REDACTED:github_token]`. That is presence only, like `factory doctor`. A value is also matched as it appears inside a JSON string (escaped), and longer values are replaced first, so overlapping values go whole. Redaction is idempotent.
- **Redaction runs at the choke points, before anything is stored.** Rather than redacting at each place untrusted text enters (Harness output, verification output, the Task Result file, the diff in the Review Packet, error messages, …), where one missed path leaks, the runtime redacts where everything leaves it:
  - **The database:** `openDatabase(path, { redact })` wraps every prepared statement so each string bound to it is redacted before it executes. Every row, and every event, is written through it, so the events API and the SSE stream (both read from the `events` table) can only carry redacted text. A mutation check confirmed it matters: without it the diff in the stored Review Packet leaked the secret.
  - **Artifacts:** `ArtifactStore.writeContent` redacts every string of the content before serializing it, so the content hash is over the redacted bytes and the JSON stays valid.
  - **The runtime log:** the runtime's own stdout and stderr (which `factory start` sends to the runtime log file) are redacted.
  - **The Harness:** `redactingHarness` (in `@factory/harness`) redacts the prompt before a Run starts, so no secret the factory knows of is passed to an agent (for example a secret in the reviewed diff), and redacts the Run's output and events before the runtime reads them.
- **Consequence: what is stored is what is used.** A Plan whose verification command contains a secret value is stored redacted, and the Task runs the stored, redacted command. That is intended: a proposal is untrusted, and history must not hold the value.
- **Harness output is now stored.** Each developer and reviewer Harness Run of an Attempt writes a `log` Artifact (`source: harness`, role, `n`, Harness id, execution id, exit, duration, output), recorded in the same transaction as its `harness_run.finished` event, which gains `outputArtifactId`. Verification `log` Artifacts gain `source: verification`. The schemas are `LogContentSchema` in `@factory/domain`. Progress events are still counted, not stored: the Fake's only event repeats its output; storing a real Harness's transcript comes with its adapter.
- **`GET /v1/jobs/:id/logs`** lists the Job's Attempt `log` Artifacts in the order they were stored, with the Task key and Attempt number, and the content. **`factory logs <job> [--json]`** prints them, one heading per Harness Run or verification command. Proposal-Stage output stays in its Artifacts (`job show`).
- **Not covered (known limitations).** The Worktree, the Factory Clone and git history can hold a secret the Harness wrote into a file: they are the Repository's content, not the factory's history (a secret scan Gate is later). A secret the factory does not know of and that matches no pattern is not redacted. Output beyond the 1 MiB limit is cut at the start, so a secret straddling the cut can leave a fragment that matches neither its value nor a pattern.
